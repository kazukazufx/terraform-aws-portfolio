# 想定要件

## 背景

個人の就職活動用ポートフォリオを、AWS上で安全かつ再現可能に公開する。アプリケーションの機能量ではなく、クラウド基盤の設計、IaC、デプロイ、監視、障害対応を評価対象とする。

## 利用条件

- 主な利用者は採用担当者と面接官
- 通常は低トラフィックで、面接前後に一時的なアクセス増加を想定
- 個人情報や決済情報は保存しない
- 主リージョンは東京リージョン
- 月額予算は変数で設定し、超過前に通知する
- 公開終了時にアプリ基盤をまとめて削除できること

## 機能要件

- HTTPSでポートフォリオ画面を公開する
- ステータス、制作物一覧、API仕様を閲覧できる
- 制作物データをPostgreSQLへ保存する
- GitHubへのPushを起点にコンテナを更新する
- Terraformで同じ構成を再作成できる

## 非機能要件

| 観点 | 要件 | 実装・確認方法 |
|---|---|---|
| 可用性 | ALBとサブネットを2 AZへ配置 | Terraform test、構成図 |
| セキュリティ | DB非公開、最小限の通信、長期AWSキー不使用 | Security Group、OIDC、Secrets Manager |
| 運用 | 異常なターゲットとALB 5xxを検知 | CloudWatch Alarm、SNS、障害演習 |
| 変更管理 | Pull Requestで検証し、承認後のみApply | GitHub Actions Environment |
| 復旧 | ECSは自動再作成、DBは日次バックアップ | Circuit Breaker、RDS backup、Runbook |
| コスト | 固定費を説明し、不要時に削除可能 | Budget、費用試算、Destroy手順 |

## 対象外

- 複数リージョンの災害対策
- 24時間365日のSLA保証
- 本番個人情報の保存
- 無停止のDBメジャーバージョン更新
- SOC 2やPCI DSSなどの認証取得

対象外を明記することで、個人作品の制約と商用本番環境との差分を説明できるようにする。
